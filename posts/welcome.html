    从一个空仓库开始：这个站是怎么搭起来的

    2026 年 10 月 18 日阅读 — 次 约 5 分钟读完
    • 建站
    • GitHub Pages
    评论 ↓
    学习工作

    这个站点没有用任何静态站点生成器。三个文件，一次提交，GitHub Pages 就会把它变成一个能访问的网站。 听起来简陋，但它有一个好处：任何一次修改，我都能立刻知道它会影响哪里。

    为什么不用框架

    Hugo、Jekyll、Astro 都很好，但它们都要求我先理解一套约定：目录放哪、前置元数据怎么填、模板语法怎么写。 而我想写的东西，本质上就是几段文字加一张图。于是问题变成了： 我到底是想要一个博客，还是想要一个能写博客的系统？

    工具应该消失在工作里。当我在写一篇文章时，最好完全感觉不到工具的存在。

    三个文件的分工

    • index.html：结构与内容，也是文章列表的入口。
    • assets/css/reading.css：所有样式，用 CSS 变量管理颜色，暗色模式只是换一组值。
    • assets/js/main.js：主题切换、移动端菜单，一共不到一百行。

    如果需要新的样式，我加一条规则；如果需要新的交互，我加一个函数。 没有打包、没有依赖树、没有node_modules。

    一段最小的 HTML

    文章页的骨架其实就这么点东西，剩下的全是 CSS 的事：

    <article class="post">
  <header class="post__head">
    <h1>标题</h1>
    <div class="post__meta"><time>2026-10-18</time></div>
  </header>
  <div class="prose">
    <p>正文……</p>
  </div>
</article>

    用 CSS 变量做主题

    所有颜色都定义在 :root 里，暗色模式只覆盖同名变量。 这样切换主题时，不需要改任何一条具体规则： 

    :root {
  --bg: #f5f7f6;
  --text: #24352f;
  --accent: #386a55;
}

[data-theme="dark"] {
  --bg: #141c1b;
  --text: #dce7df;
  --accent: #91c4a7;
}

    发布流程

    1. 在仓库里新建或修改页面文件。
    2. 提交并推送到 main 分支。
    3. 等一分钟，GitHub Pages 自动构建完成。
    文件作用要不要常改
    index.html首页偶尔
    posts/*.html文章每次写作
    reading.css样式很少

    接下来想加的东西：标签归档、全文搜索、RSS。 每一样都可以用几十行原生代码做到——只要我还没被“框架”这两个字劝退。
